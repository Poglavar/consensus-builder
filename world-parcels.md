# World parcels plan

## Goal and first deliverable

Let someone choose any city, then use real cadastral parcels when an open source is available. Start now with a **world parcel-source registry** and research cities **one at a time**, beginning with the largest cities. Do not infer that a portal has usable parcel data merely because its map or website loads.

The first research pass discovers and records sources. Source-specific parsing, browser downloads, and the three no-source choices follow once the registry's evidence format is working. Keep the city gazetteer separate from the parcel registry: a city can exist in the former while its parcel status is still unknown.

## Current app findings (28 September 2026)

- `frontend/js/city-config.js` has a fixed `CITY_CONFIGS` list and a city dropdown built from it. The location button chooses the *nearest configured* city, even if the user is far outside that city's coverage. Geolocation errors currently end in an alert.
- Several cities already share a source: Zagreb, Split, and Šibenik all use the Croatian `oss-wfs` source. The registry must describe source coverage separately from city records.
- `CadastralParcelRepository` retains immutable parcel facts during a session, while `LiveParcelFabric` and `ParcelPresenter` manage derived ground and display. Browser persistence is city-scoped, but it is not yet a cache for arbitrary world sources.
- Some proposal geometry and corridor handling already work without a parcel hit. A complete “no parcel data” mode does **not** yet work: `frontend/js/proposals/cadastre-ancestry.js` rejects publishing without explicit cadastral IDs, `backend/routes/proposals.js` rejects an empty `cadastreParcelIds` array, and building/structure apply paths require cadastral anchors. This needs a dedicated end-to-end change, not just a hidden parcel layer.

## Flow A: choose a city

1. Keep the current configured-city picker for places the app fully supports. Add **Enter your city** beside it. If geolocation is denied, unsupported, times out, or cannot confidently resolve a city, reveal and focus that input with a short explanation. A user who declines the browser permission prompt can also open the input manually.
2. Use the [GeoNames city extract](https://download.geonames.org/export/dump/readme.txt) as the initial autocomplete source. Build a locally served, searchable catalog from `cities15000.zip` for the first version; consider `cities5000.zip` or `cities1000.zip` when coverage and bundle size are measured. GeoNames supplies a stable `geonameid`, name, country code, admin codes, and WGS84 latitude/longitude under CC BY 4.0. Show attribution. Use its [country information file](https://download.geonames.org/export/dump/readme.txt) for country names. Avoid a browser call to the public service on every keystroke.
3. Show suggestions as **City, Country**. Preserve separate entries with the same name, including within one country; show region as secondary disambiguation. Identify the selection by GeoNames ID, never by display text. Keep the source coordinates in the city record. Rank exact matches and more populated places first without deleting smaller namesakes.
4. If geolocation succeeds, resolve the coordinate against the same city catalog, with a distance/coverage sanity check and a confirmation when ambiguous. Do not silently snap a user on another continent to an existing configured city. Selecting an unconfigured city creates a city-scoped runtime descriptor and centers the map there; it must not fall back to New York through current `CITY_CONFIGS` defaults.

## Flow B: find the city's parcel source

1. Look up a verified registry match by point/coverage and administrative scope. One source may cover a country, a state, or one city. A city-to-source association references the source record; it does not copy the endpoint into every city.
2. A registry entry is **verified** only after a real request returns HTTP 200 (or 206 for a documented Range read of a bulk file) **and a nonempty list of parcel-like records** for a small area in or near that city. At this research stage, record the returned format without requiring a normalized schema. A 200 map page, a tile image, a service description, an empty result, or a blocked request is not success.
3. For each attempt, save a JSON evidence file containing the exact safe request URL and parameters, UTC timestamp, HTTP status, content type, spatial test area, record count and list path, plus the raw reply (or an encoded raw body if the service does not return JSON). Redact credentials and personal data; query a small area rather than saving a whole country's parcels. Record licensing, access limits, CRS, ID field, pagination, and update frequency when known. Separate **found**, **researching**, **no open source found after documented attempts**, and **temporarily unavailable**. A failed request never becomes a permanent “no source” verdict.
4. Search cities sequentially using a fixed queue from [UN World Urbanization Prospects 2025](https://population.un.org/wup/). The 2025 ranking begins with Jakarta, Dhaka, and Tokyo. For each city, search official cadastre and open-data portals first, test a small spatial query, save the evidence JSON, then update its registry status before moving to the next. Record searched portals even when no endpoint is verified. Reuse a verified country/state source for later cities inside its coverage, but still test a representative request for each newly claimed area.

`world-parcels/registry.json` now records the **top 200** cities in the UN 2025 queue ([`queue-top200.json`](world-parcels/queue-top200.json)) and a probe of **194 countries**, after a first pass and a retry pass with browser-like headers and viewer inspection. **59** cities have a bounded parcel sample; 141 have no verified response, and **49** of those are `temporarily_unavailable` (hosts unreachable or challenge-protected from the research environment, including most .gov.cn, .ir and Indian state hosts). None of the verified samples is proven complete for its city. See [`world-parcels/FINDINGS.md`](world-parcels/FINDINGS.md) for the consolidated findings and lessons, and [`world-parcels/SUMMARY.md`](world-parcels/SUMMARY.md) (generated by `summarize-registry.py`); per-city and per-country evidence is in `research/`, `research/countries/` and `research/retry/`, merged by `merge-registry.py`, with the shared method in [`RESEARCH-PROTOCOL.md`](world-parcels/RESEARCH-PROTOCOL.md).

### Coverage page and countrywide evidence

[`world-parcels/coverage.html`](world-parcels/coverage.html) reads the registry and per-city research JSON. Serve the repository with `python3 -m http.server` and open `/world-parcels/coverage.html`. Its only basemap is [Natural Earth 1:110m country borders](https://www.naturalearthdata.com/about/terms-of-use/), kept locally in `world-parcels/countries.geojson`. Green circles require a source-linked HTTP 200 response with a nonempty parcel list; red circles mean **attempted without a verified sample**, including temporary outages and untested candidates. Zagreb (outside the UN queue, `researchOrder` 201) is marked because the app already runs on Croatia's cadastre; other cities outside the queue are not.

The `countryCoverage` array is generated by `merge-registry.py` from every country that passed the **two-region test** (polygons from two or more distinct regions of one service); each entry carries `reviewed: false` and its caveats, and the page says so. The stricter bar below is the *review* standard, not the display rule, and no country has met it yet: mark a country reviewed only when an official source explicitly claims nationwide parcel coverage, a nonempty parcel response has been verified in at least two geographically distinct regions, the same source/schema covers those regions, and known exclusions or access restrictions have been recorded. A city or province source does not qualify. South Korea's continuous cadastral dataset is the strongest national candidate so far, but its catalog page alone is insufficient; Mexico City's release covers its 16 boroughs only; São Paulo's release covers its municipality only.

### Country probes (194 countries)

Each country has `research/countries/<ISO2>.json` answering whether a country-wide online cadastre exists, with access model (open, registration, paid, viewer-only) and any provincial services. Statuses are agent-reported and then normalised in the registry: labels the evidence did not support (Brazil's rural self-declared SICAR polygons, Mali's south-west-only layer, South Africa's third-party copy, bulk-file or single-municipality samples such as Uruguay, Latvia, Singapore, Hungary) become `partial_or_unofficial_sample`, and French overseas territories are `covered_by_parent_source`. The **50** countries labelled `national_online_cadastre_verified_sample` each returned polygons in two or more distinct regions from one official-looking service, but licences are unread and none has been reviewed for an explicit nationwide claim and known exclusions, so every `countryCoverage` entry stays `reviewed: false`. A country probe of `temporarily_unavailable` (78 countries after the retry pass) means the research network could not reach the host, not that no cadastre exists; retry from another network before treating any as absent.

Croatia was first recorded as credentialed after a bare request returned 401; replaying the app's own public-token query with browser-like headers returned parcels in Zagreb, Split, Osijek and Rijeka, so it is now verified. Other credentialed or viewer-only entries may hide the same pattern and are worth re-checking through the official viewer's network calls, and retrying with browser-like headers and from an in-country network (some hosts also deny foreign IPs).

The retry pass (2026-09-30) re-probed 139 non-verified countries and 59 unavailable or candidate cities. Three techniques changed results: reading the official viewer's JavaScript and config for the real service URL (Belarus, Benin, Cyprus, Jamaica, Jordan, Kosovo, Sweden, Trinidad and Tobago, New Delhi, Pune and others), a cookie jar for cookie-dependent redirects (England and Wales, Manchester, London), and a viewer-origin `Referer` header (Belarus). Plain browser headers alone changed almost nothing; where hosts still failed, many showed 403, 418 or connection-reset patterns consistent with geo-blocking or bot protection, which is unconfirmed and needs an in-country network to settle. Retry evidence stays in `research/retry/`; the original evidence files are unchanged.

The Europe focus pass (2026-09-30) re-probed the 33 European countries that were not green, working from the national INSPIRE catalogues (the EU geoportal's search API now redirects to data.europa.eu) and the official viewers' own code. It added Belgium, Switzerland, Liechtenstein, Latvia, Iceland, Faroe Islands, Guernsey, Isle of Man, Albania, Greece, Malta, Portugal and Slovakia. Greece and Slovakia are bulk downloads read by HTTP Range rather than query services; Portugal's service is mainland-only; Hungary's INSPIRE WFS turned out to be a small sampling area. Moldova is explicitly geo-blocked, and Serbia, North Macedonia, Ukraine, Russia and the Caucasus reset connections from this network, so they need an in-country test. Romania's geoportal is restarting in phases and should be retried.

**Federal countries are tracked by region.** In the United States, Canada, Australia, Germany, Switzerland and Belgium the cadastre is a state, province, canton or Land matter, so a country-level "no national service" hides real coverage. The registry's `subnationalCoverage` records each region (`research/subnational/` and the Länder/canton lists in `research/europe/`): 32 of 51 US states have an open statewide layer and the other 19 have county layers; 7 of 13 Canadian provinces and territories; 7 of 8 Australian states; 14 of 16 German Länder (Bavaria credentialed, Berlin's certificate chain fails from here); 18 of 26 Swiss cantons verified open on the national geodienste.ch WFS, 2 open but incomplete (Ticino, Valais), 6 gated by contract or release; all 3 Belgian regions; 10 of 24 Argentine provinces have a province-wide open service (Córdoba, Entre Ríos, Chaco, Neuquén, Río Negro, San Juan, Tierra del Fuego, Salta, Buenos Aires province by point query, and the city of Buenos Aires); Brazil has one state-level urban layer (Federal District) plus municipal lots in four capitals, and every other state offers only SICAR, the self-declared rural registry, which is counted separately; Mexico has no reachable state-wide service, six municipal or third-party partial samples, and most state hosts reset or block from this network. Malaysia has four state-wide lot layers (Selangor, Terengganu, Penang, Perak) with the rest gated or unreachable; Indonesia's national land-ownership service has sublayers for 15 of 38 provinces, all of them small survey packages that return nothing in the provincial capitals. Rwanda's National Land Authority publishes its register as one open layer per district (21 of 30 verified, Kigali with 555,857 parcels), which also makes Rwanda a nationally verified country. A developed-country re-check added Japan, Singapore, Uruguay and Colombia; Hungary turned out to sell its cadastre, and South Korea's is free but only reachable through VWorld with a key. The coverage page shades these countries lighter and shows the region counts on hover. US parcel layers often carry owner names and mailing addresses; saved samples hold only IDs and geometry. Licence terms have not been read for most regional layers.

Known evidence caveats: Berlin's sample was relayed through a summarising tool rather than saved from a raw reply, so it is downgraded to a candidate until re-fetched directly. Several samples come from unofficial third-party layers (Luanda, Lima, Lusaka, Guayaquil, Birmingham, South Africa) with unconfirmed publishers and terms. Saved replies exclude owner names and other personal data.

### Verified-source browser loading

- Add source adapters only after discovery proves the endpoint. An adapter converts the source's response to the repository's canonical GeoJSON parcels with stable IDs and explicit provenance. Support viewport-sized, paginated requests; do not download an entire country to enter one city.
- Check coverage and coordinate system before drawing. Treat CORS, authentication, rate limits, partial pages, and outages as distinct retryable states. Use a backend proxy only for sources whose terms permit this and where it is needed.
- Cache fetched source chunks in the user's IndexedDB, keyed by source ID, version, city/coverage, spatial chunk, and adapter version. Retain them for a defined limited period with a size cap and eviction; make cache clearing possible. The cadastral repository remains the in-session authority, and the live fabric remains a derived presentation.

## If no verified open parcel source is available

Show: **“We could not find an open data source for your city's parcels.”** Offer explicit paths. Continue to offer these when research is incomplete or a source is temporarily unavailable, with wording that states the actual status.

**Built (October 2026):** the screen exists as `frontend/js/parcels/ground-fallback.js`. A visitor first sees the official register attempted; when that viewport fetch fails, or the city's config says `parcels.strategy: 'none'`, the screen names which of the two happened (a failed request is never reported as "no register", and the reverse) and offers four ways on: **retry** (only when the failure reads as temporary), **enter your own link to a register** (path 1 below, with the sample validation it describes), **estimate parcel boundaries from satellite imagery** (best-effort recognition that may be incomplete or wrong and does not establish legal boundaries; the entry point reports that it is unavailable until a module registers `window.ParcelOcrJobs`, the working-name integration contract), and **apply a Schelling point algorithm** (see [`schelling-parcels.md`](schelling-parcels.md)). A choice becomes the parcel source for that city for the browser session only; nothing is promoted to the registry.

1. **Enter a parcel-data URL.** Initially accept documented GeoJSON FeatureCollection, OGC API Features, or ArcGIS FeatureServer query URLs through constrained adapters; add WFS/GML or archive formats only with parsers. Fetch a bounded sample, report CORS/auth/size errors, and check that features are closed Polygon/MultiPolygon rings, have plausible coordinates/CRS, and overlap the selected city's vicinity. Reject malformed or remote geometry and duplicate unstable IDs. If valid, show a preview and load viewport chunks into the same repository/cache path. A user-supplied URL is not automatically added to the public registry; review its rights, stability, and coverage first.
2. **Guess parcels.** This is an explicitly estimated layer, never labelled cadastre. Use available satellite imagery rights, OSM buildings/roads, and local geometry heuristics: avoid splitting individual homes where evidence supports it, but allow for OSM footprints that aggregate buildings across several parcels; road edges constrain fronts; rectilinear/orthogonal candidates should be preferred where appropriate. Voronoi is only a seed. Evaluate a self-hosted segmentation model such as SAM 3 for boundary hints, then vectorize, close, and validate polygons. Use no paid LLM calls or LLM tokens in this pipeline. Store confidence/provenance, expose manual corrections, and do not treat inferred boundaries as ownership evidence.

   Initial Zagreb CDOF spike and two cadastral holdout comparisons: [`world-parcels/guess-spike/README.md`](world-parcels/guess-spike/README.md). The tested distance and imagery-gradient candidates are research artifacts; neither is ready for the app layer.
3. **Apply a Schelling point algorithm.** A parcel plan every visitor can derive independently and arrive at the same result, so it needs no authority and no negotiation: the first one is *meridians and parallels* (Angel's ~1 km arterial grid laid on the graticule, superblocks cut into blocks by integer division), an elevation-contour (isohypse) plan is the planned second. It is explicitly an estimate for planning, labelled as such, drawn in memory and never saved as a register. Details in [`schelling-parcels.md`](schelling-parcels.md).
4. **Proceed without parcel data.** Let proposals attach to authored geography and city identity. Audit creation, publish validation, backend schema/routes, apply/unapply, sharing, selection, consent/ownership, and calculations that currently assume `cadastreParcelIds`. Establish explicit geography-only semantics and disable parcel ownership/consent actions that require real cadastral IDs. Test a create → save → reload → share → apply → unapply loop for at least one corridor, structure, and building proposal in a city with no parcels.

## Implementation order and acceptance checks

1. **Registry research now:** keep `world-parcels/registry.json` and per-attempt JSON evidence, advancing the UN queue one city at a time. A successful record has an HTTP 200 request, a nonempty parcel list, and a saved reply or privacy-safe preview. A negative record names the portals and requests checked, the date, and the remaining uncertainty. Maintain the coverage page from the registry.
2. Build the GeoNames catalog and city-input flow. Check geolocation denial/timeout, a city absent from `CITY_CONFIGS`, two same-name cities in one country, and a location far from every configured city.
3. Add one verified source adapter and the bounded IndexedDB cache; prove a first fetch, reload from cache, expiry, and an outage retry.
4. Add URL import with geometry/location validation, then the geography-only proposal path. Audit every parcel-ID gate above and test the full lifecycle before exposing that option.
5. Prototype inferred parcels separately, compare samples with real cadastre where available, and only then expose the estimate path. Never promote an estimate to official source status.
