Take your plan with you

In Designs → Share applied designs, choose the designs to include, then download the editable plan or GeoJSON. Excluded designs stay excluded. The Share action on an individual design also offers Download design. No account, wallet or publication is needed for file downloads or imports.

FormatUse
.ugt.jsonEditable backup and restoration in UGT; open JSON for other software.
.geojsonGeographic drawings in GIS software such as QGIS. Not an editable UGT backup.

Restore an editable plan

Choose Import plan file in Designs or the share panel, select a .ugt.json file and review its name, location and members. Import as drafts adds the designs without applying them or replacing existing work. An identical existing design is reused. Imported plans remain listed on this device under Imported plans, including their saved view. Open one to select its members, download it again or publish it through the usual sharing controls. Apply individual drafts when you want to add them to the map.

Closing the review or pressing Cancel writes nothing. Choosing the same file again is supported. Browser storage must be writable; the app saves the imported designs and plan membership in one transaction.

Open, versioned JSON

The top-level schema is ugt-plan-file/v1. The file contains an ordinary plan/v1, all its canonical design/v1 members and optional source references. The plan owns membership and its saved geographic view. Every member CID is verified against its embedded content. The JSON preserves authored geometry, holes, parameters, furniture definitions, title, authorship and location. Local application caches are regenerated when a design is applied.

{
  "schema": "ugt-plan-file/v1",
  "plan": { "schema": "plan/v1", "title": "My plan",
    "designCids": ["…"], "view": { "at": "45.8,15.96,17", "mode": "2d" } },
  "designs": [{ "cid": "…", "content": { "schema": "design/v1", "…": "…" } }],
  "designSources": { "…": { "sourceId": "…", "snapshotId": null } }
}

This abbreviated example shows structure, not a valid complete file. See the JSON Schema and the shared reference codec. Schema validation also requires the codec’s CID, geographic-coordinate and resource-limit checks. Unknown envelope versions are refused, rather than interpreted as this version.

Dependencies and source data

Uploaded building models referenced by modelUrl are embedded as self-contained GLB data. If an asset cannot be fetched, is too large, or references external images or buffers, the editable download fails with a reason. Embed those resources in a GLB and retry. Embedding changes that design’s content CID and the file’s plan membership CID; it does not change the original design or its published links.

Source IDs and known snapshot IDs are references, not copies of cadastral, imagery, terrain, existing-building or planning datasets. You can restore and edit authored content without fetching them. Applying it against cadastral ground, recalculating derived effects and reproducing the complete backdrop require the relevant source services. A source with no retained snapshot may change. Imported source references are not evidence of land ownership or coverage.

GeoJSON interoperability

GeoJSON exports WGS84 longitude/latitude in degrees. Features identify the design CID and their role: site, building footprint, corridor, structure, plot or other authored geographic layer. Polygon holes and MultiPolygons are retained. Sites and drawings can overlap; adding every feature’s area double-counts land. Scalar authored attributes are carried alongside ugt_* identifiers.

It excludes generated meshes, local floor-plan coordinates, source basemaps and agreement terms. Heights are authored parameters, not an exported mesh; any third coordinate retains its original vertical basis, without claiming a surveyed elevation datum. GeoJSON export does not need to download model assets. UGT file import accepts the editable JSON format; ordinary GeoJSON uses the app’s separate geometry authoring tools.

Limits and privacy

Files are limited to 32 MiB, 1,000 designs, 200,000 total geographic vertices, 40 nesting levels and 1,000,000 JSON values. Closed rings and finite, bounded coordinates are required. These checks bound input; they do not certify polygon topology or engineering suitability.

Files contain authored content, including descriptions and the author name. Review that content before sharing. They exclude wallet/session state, credentials, private preview references, publication marks, agreement decisions, signatures, ownership claims and execution state. An imported file grants no consent or rights. Existing public share links keep their behavior.

3D interchange

This release does not download the visible proposal scene as GLB. The renderer combines proposals with terrain and existing context, uses a local Web Mercator frame with latitude-dependent scale, and applies custom display shaders. A scene exporter still needs a reliable proposal-only selection, visibility handling and documented conversion to metre units and glTF axes. Embedded uploaded GLBs preserve those authored model assets; they are not an export of the composed 3D scene.
