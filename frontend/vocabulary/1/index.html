What the records mean

Version 1 defines the terms used by the published proposal and named-plan JSON-LD views. Records, geographic extents, declarations and commitments have distinct meanings.

Download JSON-LD definitionsClassesPropertiesConcepts

Read a published record

Append ?format=jsonld to a proposal or named-plan detail URL on the API: /proposals/{rowId}?format=jsonld or /plans/{slug}?format=jsonld. Each response includes its context, so a consumer can expand it without fetching a remote context.

Record IRIs use the deployment's configured canonical API URL. Row IDs are scoped to that publication store. Authored IDs, chain locations and member hashes are separate values.

A recorded lifecycle is not independent evidence of execution. An authored site is not a legal parcel boundary. A saved member hash commits to the application's member content, not to every field in the JSON-LD view. These exports make no assertion of ownership, consent or physical construction.

Record and reference classes

Published proposal

cb:Proposal

An authored proposal record in a publication store. Its existence does not assert construction, ownership or legal approval.

Named plan

cb:NamedPlan

An immutable named commitment to an ordered set of proposal members and their saved content hashes.

Plan membership commitment

cb:PlanMembership

A position in a named plan, identifying a published proposal and the member content hash saved when the plan was named.

Proposal site

cb:ProposalSite

The geographic extent authored as the proposal site. It is not a legal cadastral parcel or an assertion of a constructed project.

Declared cadastral reference

cb:CadastreReference

A cadastral identifier declared by this proposal. This node is scoped to the proposal; it does not establish cross-provider parcel identity.

Declared chain reference

cb:ChainReference

A complete chain family, network, contract or program, and token or account location declared by the server-owned attachment. This alone is not verified execution evidence.

Relationships and values

Publication row ID

cb:proposalRowId

Decimal database row key within the canonical publication API.

Range: xsd:string

Authored proposal ID

cb:authoredProposalId

Authored identifier carried by the published record, separate from a database row key or chain account.

Range: xsd:string

Author label

cb:authorLabel

A stored author attribution string; not a verified person, organization or signing authority.

Range: xsd:string

Declared design goal

cb:declaredGoal

The exact design-goal string carried by the record, including unclassified values.

Range: xsd:string

Design-goal concept

cb:designGoal

An exact match to the current design-goal concept scheme; not a physical-object classification.

Range: skos:Concept

Decision kind

cb:decisionKind

The decision kind interpreted by the current application contract. A missing historical kind is interpreted as owner-deal.

Range: skos:Concept

Recorded lifecycle

cb:recordedLifecycle

The API record lifecycle, including its Active-only deadline rule. This is not an independently observed chain or construction state.

Range: skos:Concept

Proposal deadline

cb:proposalDeadline

The deadline carried by the proposal. It does not promise a settlement or construction time.

Range: xsd:dateTime

Authored site

cb:site

The geographic site declared by this proposal.

Range: cb:ProposalSite

Declared cadastral reference

cb:cadastreReference

A proposal-scoped declaration of a cadastral identifier.

Range: cb:CadastreReference

Declared identifier

cb:declaredIdentifier

The exact identifier string in a scoped reference.

Range: xsd:string

Declared chain location

cb:declaredChainReference

A complete location from the server-owned chain attachment; not proof of current chain state.

Range: cb:ChainReference

Chain family

cb:chainType

Declared blockchain family, such as evm or solana.

Range: xsd:string

Chain network

cb:chainId

Declared network identifier in the chain family.

Range: xsd:string

Contract or program

cb:contract

Declared contract or program identifier. Case is retained.

Range: xsd:string

Token or account

cb:tokenId

Declared proposal token or account identifier. Case is retained.

Range: xsd:string

Offered consideration

cb:offeredConsideration

An explicit authored offer amount and currency. It is not a balance, paid amount or escrow observation.

Range: schema:MonetaryAmount

Authored budget

cb:budget

An explicit authored budget amount and currency, distinct from offered consideration.

Range: schema:MonetaryAmount

Ordered memberships

cb:memberships

An RDF list of the plan membership commitments, preserving their saved order.

Range: rdf:List

Member proposal

cb:member

The published proposal record named by a membership commitment.

Range: cb:Proposal

Committed member hash

cb:committedMemberHash

Saved SHA-256 memberContent digest, under the application commitment contract; not a digest of this JSON-LD document.

Range: xsd:string

Current member hash

cb:currentMemberHash

The current memberContent digest calculated during this read, when the member exists.

Range: xsd:string

Member changed

cb:memberChanged

True when the current member is missing, has invalid commitment content, or its memberContent digest differs from the saved commitment.

Range: xsd:boolean

Member missing

cb:memberMissing

True when the referenced member could not be found during this read.

Range: xsd:boolean

Member content invalid

cb:memberInvalid

True when the current member exists but cannot be hashed under the current readjustment commitment contract.

Range: xsd:boolean

Saved plan hash

cb:planHash

Saved aggregate commitment over ordered authored proposal identifiers and member hashes. It does not identify every field in this export.

Range: xsd:string

Supersedes named plan

cb:supersedes

An explicit link to the previous named plan revision.

Range: cb:NamedPlan

Superseded by named plan

cb:supersededBy

A named plan that explicitly declares this plan as its previous revision.

Range: cb:NamedPlan
