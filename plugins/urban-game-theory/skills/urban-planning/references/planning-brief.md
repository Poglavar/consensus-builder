# Planning brief

Use this as a working structure, not a mandatory questionnaire. Reuse known information and ask only for missing decisions that affect the immediate work.

| Topic | Capture when relevant |
| --- | --- |
| Place | Location, jurisdiction, site/study boundary, known parcel IDs, surroundings |
| Purpose | Decision to support, intended audience, site plan or master plan, stage of work |
| Programme | Uses, approximate capacity, facilities, public space, priorities and flexibility |
| Context | Existing uses/buildings, street connections, terrain, services and important local conditions |
| Constraints | Confirmed planning controls, protected features, access, hazards, infrastructure limits |
| Values | Outcomes the user prioritizes and trade-offs they are willing to consider |
| Delivery | Time horizon, phases, dependencies, known budget or implementation assumptions |
| Output | Desired map/drawing/report, available source files, requested units and formats |

For a first pass, location/boundary, purpose, and principal priorities are often enough to begin. Defer details until they affect a design decision. Record assumptions visibly and revise them as better information arrives.

Suggested brief structure:

1. Develop a [type/stage of plan] for [site or study area] to support [decision].
2. Prioritize [stated outcomes], working within [confirmed constraints].
3. Test [meaningful design choices] and assess them using [agreed measures].
4. Deliver [supported outputs]. Track [critical missing evidence] as unresolved.

Never fill these fields with invented local facts. An illustrative assumption is acceptable only when labelled as such.
