# Saved workspace with one editor

User decision: keep one saved map workspace per browser profile for this site, with one editable map tab. Do not create automatic copies or offer an independent-copy action. This supersedes the earlier per-tab copying policy.

## Current contract

- The workspace identity lives in durable browser storage, independently of a tab session. Closing the tab does not remove its saved designs, agreements, application state, drafts or modeling inputs. Reopening resumes the same identity and records.
- One fixed, exclusive Web Lock gates all editing in this browser profile/site origin, including different-city map tabs and simultaneous first visits before an identity has been saved. A second map tab shows a full-page notice with one retry action. It does not create another workspace, open a writable private cache or enter a recovery-copy mode.
- Closing the owner releases the lease. Retry reloads the waiting tab at its requested address and opens the same saved workspace. Closed-tab session restoration is not required.
- Geographic contexts retain separate IndexedDB databases. Editor drafts and their active identity belong to the saved workspace. Opening another city later does not load another city's records into its composition.
- Browsers without Web Locks cannot open an editable workspace. They show an update notice; no uncoordinated writer or copy fallback is enabled.
- Existing current per-city storage can initialize the saved workspace once. The tab-copy ancestry and fallback paths are removed. Previously created experimental copies are not merged or exposed as an additional workflow.

## Ownership and startup boundaries

The workspace storage adapter buffers authoring writes until ownership is decided. Refused tabs cannot persist them. The ID is checked again under the lease to prevent a delayed first visit from replacing an identity established by another document.

`PersistentStorage.ready` stays pending when ownership is refused. Existing initialization/replay callers therefore cannot proceed. Its mutation APIs also reject writes after ownership is released, preventing a suspended or stale editor from writing into the next owner's state. The draft singleton and its unload flush are installed only in the owner.

The blocked notice must be able to load translations without opening map storage; otherwise it waits forever on its own ownership barrier. The early map URL writer also checks ownership, preserving incoming design/plan links while blocked. After retry succeeds, normal geographic URL synchronization resumes. The map boot watchdog does not report an intentionally blocked editor as a failed startup.

The interface uses a full-page state with no editable map or dismiss control. The retry button uses the existing translated action label. Mobile and desktop captures are generated by the focused browser specs.
